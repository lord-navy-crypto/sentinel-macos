# Sentinel v2.3 — Pre-Regression Gate and Real macOS Test Matrix

Branch: `upgrade/v2.3-stable`

This document separates **engineering preparation** from **real-device validation**. Passing the automated gate means the branch is ready to begin regression on actual macOS systems and packaged artifacts. It does not certify a release by itself.

## 1. Automated gate before real-device testing

The branch CI must pass all of the following on the same HEAD:

1. `go test ./...`
2. dedicated v2.3 migration / Incident / timeline / export / Storage aging / registry / Vault / navigation / pre-regression contract tests
3. Darwin arm64 Go build smoke
4. Darwin amd64 Go build smoke
5. `go test -race ./...`
6. `go vet ./...`
7. JavaScript syntax checks for every shipped v2.3 bridge/workspace
8. shell syntax checks for build/package/release/verification scripts

The running app also exposes `/api/pre-regression` and `pre-regression.html`. A normal-mode launch runs v2.3 state migration **before** Behavior, Trust, Change Monitor, and Incident managers read legacy state.

## 2. State migration / rollback expectations

Legacy Sentinel-owned metadata stores covered by the v2.3 migration registry:

- `behavior-baseline.json`
- `behavior-history.json`
- `trust-profile.json`
- `trust-drift-history.json`
- `change-history.json.gz`
- `change-checkpoint.json.gz`
- `incident-history.json.gz`

Migration rules:

- decode the primary file strictly before rewriting it;
- do not force-overwrite a corrupt primary file;
- changed stores use Sentinel's atomic private state writer;
- the previous primary is retained as `.bak` for rollback;
- `--ephemeral` performs no persistent migration writes;
- Incident history v1/v2 is normalized to v3 stable object-centered StoryKeys while keeping bounded episode IDs.

### Real migration fixture test

Before RC, copy a real v2.2 Sentinel state directory to a disposable test account or disposable state location. Launch the v2.3 branch once, then verify:

- all supported stores load;
- migrated stores still contain the expected user-approved history/reference data;
- any changed store has a readable `.bak`;
- Incident history preserves evidence while merging legacy window-specific StoryKeys for the same canonical object;
- a deliberately damaged copied primary store is reported as a migration blocker and is not silently replaced;
- restoring the `.bak` returns the copied fixture to its pre-migration representation.

Do not perform this fixture test against the user's only production state copy.

## 3. Incident / Intelligence regression

Use controlled local test objects and verify:

- the same canonical object observed in separate >15-minute evidence episodes receives different episode IDs but the same stable StoryKey;
- different canonical paths never merge merely because timestamps are close;
- Explain Why emits only registered reason codes;
- deterministic rules reference registered reason codes and never execute actions;
- Grouped Timeline collapses only identical evidence fingerprints within its bounded window;
- raw Global Timeline remains available and preserves every retained event;
- Incident JSON export includes stable ID, episode ID, reason codes, ordered timeline, evidence, limitations, and privacy statement;
- exported Incident JSON does not contain the investigated file contents or raw Terminal output.

## 4. Continue Investigation / Investigation Sessions

Verify on real applications, plists, dylibs, XPC services, scripts, and ordinary files:

- app bundle traversal stays bounded;
- broad directory scans stop at nested bundle boundaries;
- plist executable continuation resolves only explicit absolute local targets;
- runtime PID / parent / TCP / open-file / launch persistence correlations match current macOS evidence;
- session branch autosave does not copy a note from the previous branch;
- explicit Save Session and Bookmark preserve the user's current branch note;
- session persistence survives a normal Sentinel restart;
- `--ephemeral` session history remains memory-only;
- Investigation Bundle export is bounded, prioritizes bookmarks/recent branches, and never copies investigated file contents.

## 5. Storage Intelligence regression

Run a real Storage Intelligence scan on a controlled scope first, then a larger user-selected scope.

Verify:

- progress is visible and cancellation returns cleanly;
- a subsequent scan can run after cancellation;
- permission errors / slow-path skips / truncation are surfaced as partial evidence;
- Storage History capture is explicit rather than silently generated by a scan;
- retained snapshots compare visible-byte/category/file-type growth correctly;
- Storage Aging buckets use modification timestamps only from the latest bounded large-file evidence set;
- oldest-file detail is bounded and paths continue into Investigation;
- retained trend points only compare the same storage root;
- the UI never describes bounded large-file aging as a complete filesystem inventory.

## 6. System Console / Control Plane regression

On the real Mac, exercise representative fixed tools from every domain:

- System & Hardware
- Security
- Processes
- Startup
- Network
- Storage
- Search
- Backup
- Power
- Logs

Verify:

- no arbitrary shell, `sh -c`, command concatenation, or web `sudo` path is exposed;
- target tools accept only a positive PID or absolute path as required;
- query timeout/output bounds are enforced;
- structured facts/records preserve raw current-query evidence underneath;
- real path/PID evidence can Continue Investigation;
- system-global SIP/FileVault state stays in Security Posture rather than becoming a fake file Incident;
- path-specific Gatekeeper/signing review evidence can participate in Incident/Reason Code correlation;
- System Snapshot & Diff correctly reports observed additions/removals and security-state changes without claiming causation.

## 7. Process / Network / Launch regression

### Process Relationship Explorer

Use several known processes and verify parent/child lineage, exact executable identity, open objects, TCP evidence, and persistence references against Activity Monitor / `ps` / `lsof` observations where appropriate.

### Network Relationship Explorer

Verify current LISTEN / ESTABLISHED relationships, explicit history capture, normalized endpoint identity, retained snapshot comparison, and the fact that refresh alone does not append history. Sentinel must not imply packet capture or payload inspection.

### Launch & Service Explorer

Verify user LaunchAgents, system LaunchAgents, and system LaunchDaemons. Confirm executable target existence, exact executable-to-PID correlation when running, plist continuation, and explanation of RunAtLoad / KeepAlive evidence.

## 8. Safe Actions / Vault / recovery regression

Use **disposable test files only**.

Verify the complete sequence:

1. preview Rename or Vault;
2. inspect dependency preview;
3. explicit user confirmation;
4. execute action;
5. inspect Action Journal and post-action observation;
6. open Vault Health;
7. verify manifest/hash/size/original path/current path and journal health;
8. restore or undo;
9. verify restored path/content/permissions where applicable.

Also verify:

- no permanent-delete action appears anywhere;
- Safe Actions refuses unsafe/system-protected/symlink-traversing cases as designed;
- failed/interrupted operations leave recovery metadata understandable rather than silently disappearing;
- Vault Health itself never calls the action-execution API.

## 9. Navigation / desktop UX regression

Every deep workspace must preserve the current localhost session token when navigating among:

- Easy — main Sentinel dashboard
- Investigate — Intelligence / Investigation / Process / Network / Launch explorers
- Advanced — Control Plane / System Console
- Recover — Vault Health

Verify browser Back/Forward behavior, investigation branch Back/Forward, Cmd+K, page refresh, and desktop embedded navigation.

## 10. Architecture and packaging regression

Automated CI cross-build proves only compile compatibility for Darwin arm64 and amd64. It is **not** equivalent to executing on Intel hardware.

Before release candidate:

- build the normal macOS app;
- build/package the Universal2 desktop artifact using the repository's supported packaging path;
- verify bundled resources include all new HTML/CSS/JS files;
- install the DMG on Apple Silicon;
- launch, quit, relaunch, and exercise all four workspace modes;
- verify code-signing / Gatekeeper behavior for the actual packaged artifact;
- verify release verification scripts against the produced artifact;
- where Intel hardware is unavailable, retain amd64 CI build coverage and explicitly mark native Intel execution as unverified rather than claiming it passed.

## 11. Exit criteria for the real regression phase

The branch may move from real regression to release-candidate preparation only when:

- the latest branch HEAD has a fully green enhanced CI run;
- `/api/pre-regression` reports no engineering blocker in the tested normal-mode state;
- migration fixture testing passes;
- all high-priority real-Mac matrix rows above have an explicit result;
- any unavailable hardware/permission/entitlement case is recorded as unverified/limited, not silently counted as pass;
- no regression introduces a permanent-delete path, arbitrary shell, hidden `sudo`, malware-probability score, or cloud requirement for core functionality;
- `main` remains unchanged until a separate explicit merge decision.
