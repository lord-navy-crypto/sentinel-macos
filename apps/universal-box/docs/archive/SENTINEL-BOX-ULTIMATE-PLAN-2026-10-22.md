# Sentinel Box 终极开发计划书（2026–2028）
**归档日期：2026-10-22 · 版本：战略基线 1.0 · 仓库永久档案**  
**执行状态：开发计划已定稿；本分支优先实施第一批两个能力，第三项视测试门禁进入下一批。**

## 一、使命与边界

打造一个**完全免费、无需订阅、离线优先、用户主动触发、普通人能懂**的日常桌面工具箱。
目标不是复制 Word、Office、Finder、Explorer、PowerToys、7-Zip 或成熟的命令行系统，而是把他们反复证明有用的“小动作”做得更好：
- 3 步内完成选择→预览→导出；失败不丢已完成工作；所有源文件保持原样；
- 免费核心功能不设登录、使用次数、云配额或订阅墙；
- 解释实际能力与局限，不标榜人工智能生成的代码天然好于历史代码；
- **没有经基准测试、持续测试、维护者反馈、兼容性/安全验证，绝不以“重写旧代码更快”作为结论**；
- 默认不联网、不扫描全盘、不后台轮询剪贴板、不作恶意软件式常驻、不绕开权限；
- 本项目**目前交付目标是 macOS Tauri App**，共享 TypeScript/React 纯核心可能在以后用于 Windows/Linux；不要把跨平台源代码兼容表述为已经发布 Windows/Linux 安装包。

## 三、仓库已存在的能力与禁止重复清单

现有 Sentinel Box 工具目录已经包含：
- PDF 合并/裁剪/加水印/表单、图像压缩转换/OCR、截图、Office 文档模板、CSV/Excel 处理；
- ZIP 压缩/精选导出/查验、重复文件、SHA-256 校验、文件元数据、重命名、目录树、数据完整性；
- 文本排序去重/编码转换/字面查找替换/文件比对/JSON 格式化与路径分析；
- QR 生成、日历 ICS、数学计算、学习卡片、笔记、密码生成；
- 近期 Draft：书签 HTML 整理、剪贴板图片 PNG、本机朗读、EPUB 章节、JSONL 结构化日志。
新能力必须先搜索 ToolLaunchpad 与相关组件和测试，查明是否已有相似功能。避免“列表工具 150 个但入口复杂”的陷阱。新增时只增一个精确目录入口，增加关键词检索而非营销性的同义入口。

### 严禁以伪功能充数

报告必须来自**真实文件字节**，不能使用用户文件名做假判断；真实“保存成功”必须来自导出回执；只预览的按钮不得标为“已修改系统”。不假称速度提升，必须有基线与对照。

## 五、首批任务：先计划归档，再严格执行两个功能

### 1. HEX Viewer（v0.83）
- 一个用户主动选择的文件；只读，最大 8 MB；默认只显示最多 64 KiB 或一个分页窗口；
- 文件大小、字节偏移（以 0 起算的十六进制）、每行 16 个十六进制字节、可打印 ASCII，控制字节显示句点；
- 显示文件头的前 16 字节，支持基于偏移量跳页、按字节值的安全精确搜索；不猜测文件类型、不伪造文件内容；
- 只读，不覆盖，不将文本显示为未经转义的 HTML；边界输入/巨大偏移/空文件清楚错误；
- 浏览器 E2E 读取真实二进制并检查偏移、字节、最后页、保存只读摘要；底层 Vitest 覆盖边界；
- 这是 Hex Fiend 的**入门只读补充**，不复制其专业大文件编辑能力。

### 2. EML Email Archive Viewer（v0.84）
- 仅处理用户主动选择的一份 .eml，最多 2 MB（首版），解析常见 RFC822/MIME 邮件头、主题、发件方、收件方、日期；
- 优先提取单个或多个 text/plain 段；至少兼容 UTF-8、基本 base64 / quoted-printable，限制解码内容；无 HTML 原样渲染；
- 附件只显示安全的元数据（文件名、MIME 类型与声明/实际体积），不执行/预览附件，不联网拉资源；
- 原始邮件字节不改动；拒绝损坏格式或无法处理的字符集时明示限制。浏览器 E2E 用真实 .eml 示例验证 MIME 与附件；
- 属于**邮件档案的本地只读查看**，不代替完整邮件客户端、不读用户邮箱/系统权限。

### 3. Grep-style Search（v0.85，下一批）
- 只对显式选择的 ≤20 个 TXT/MD/CSV 等小文本文件运行字面字符串搜索，列出路径、行号、片段；
- 与“查找并替换”区分：**不写入文件**，多文件汇总可导出 CSV；
- 正则引擎暂不默认启用，避免无界回溯造成浏览器卡死；若引入需安全引擎/工作线程和严格时间限制；
- 第一批两个功能质量合格后再做。

## 六、共同架构、发布与安全要求

1. 维持 Tauri + React + TypeScript 的现有架构，共用现有 exportFile 导出、ToolLaunchpad 检索与 App 路由；纯逻辑在 src/lib，UI 在 src/components。不要引入大型依赖、外部服务和多余后台权限。
2. **输入先验证再接纳（事务式导入）**：所有新文件按扩展名/大小/内容格式验收，失败保留前一成功结果；导出前预览真实输出；不修改原件。
3. **安全边界**：拒绝不受控 URL、HTML 执行、过量解压、多余文件遍历；严禁自动上传和任何隐蔽剪贴板收集；电子邮件、二进制等敏感内容不进入日志、分析上报或持久偏好。
4. **性能纪律**：实现有界、测最坏、限制显示条目。每轮性能提升需在**同测试环境、同文件、同内容**对照，报告中位值、内存峰值，才能宣称加速；不能因为代码由 AI 生成就认为更快。
5. **兼容性纪律**：用户可见操作须有 Vitest 边界测试、Chromium 真实文件操作测试、TypeScript、Intel/Apple Silicon macOS 双构建；不能把通过 GitHub CI 当成用户实机验证。
6. **依赖与可维护性**：锁定依赖，复用现有库，记录第三方许可证，不修改成熟库源码；不新增无测试的调用、不加入隐式后门或 telemetry。
7. **PR 治理**：既有 PR #88–#107 为堆叠 Draft，按依赖顺序复核、整合/合并；不把 v0.xx 开发里程碑冒充 DMG 真正版本。新的首批开发使用 Draft，合并与安装包发布需要单独门禁。
8. **进度证据**：每轮必须给出文件路径、commit、PR、CI 状态、自动化用例/实机限制。CI 失败要修复，不能带红发布。

## 七、验收量化指标（目标而非既有事实）

- 100% 新功能可在离线环境完成核心任务；0 必需账户；0 强制联网；
- 100% 新功能明确输入上限与失败保留旧结果；0 次悄悄删除/覆盖用户源文件；
- 每个新入口至少 2 个有效的测试样本和 2 个错误/边界样本；所有实际保存由下载的文件字节检查；
- 日常用户路径：通常 ≤3 个主动操作步骤（选文件→预览→导出）；无困难语言也能看到明确提示；
- 每个 PR 的 TypeScript、Vitest、Chromium 与双架构构建全绿后才考虑合并；至少一次真实 macOS 权限/文件选择器/导出对话框验收再发布；
- 每四个小功能安排一次“停功能、清债务”的清理迭代，防止 UI 和堆叠 PR 失控。

## 八、实施顺序与档案更新

**不可倒序**：
1. 检索官方资料和当前工具目录，确定不重复；
2. **先提交本终极计划到仓库 archive 并确认 commit；**
3. 在其基础上开发 HEX（v0.83）与 EML（v0.84），追加实际测试/QA；与计划书同一开发分支形成 Draft PR；
4. 查看 CI 的失败日志，修复、复测；实机不可完成时如实写“未验收”；
5. 更新本计划书“计划与完成对照”，按质量门禁决定下一批 v0.85；
6. 审查旧 PR 栈，统一真正发布版本、macOS 安装包与变更记录，发布后才称“用户可下载正式版”。

**文档维护**：本文件是战略基线档案，后续对顺序/优先级进行重大调整应另起日期版本并链接本版本，不静默修改既有历史。
