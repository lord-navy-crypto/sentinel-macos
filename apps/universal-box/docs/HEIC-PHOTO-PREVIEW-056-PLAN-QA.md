# Sentinel Box v0.56 · 高频图片工具开发计划与 QA 记录

**所属产品计划**：[Issue #62](https://github.com/lord-navy-crypto/sentinel-macos/issues/62) → [v0.54 实施计划](./EXECUTION-PLAN-DAILY-TOOLS-054.md) → v0.55 扫描 PDF 真压缩 → **本轮 v0.56 图片常用操作**。本轮基于上一轮开发分支（PR #80），不代表已经合并/公开发布。**原则：升级原有 `Target Size Photo Compression`，不增加同义工具入口。**

## 使用场景及具体缺口

用户在 iPhone 拍摄的 HEIC 文件无法方便地发送给只接收 JPEG 的学校、Windows 软件或老式网站。现有 Sentinel Box 支持最多 10 张 PNG/JPEG/WebP 目标 KB 压缩成 JPEG/WebP，但 **没有 HEIC 输入**、无法在下载 ZIP 前查看压缩结果，也没有“相比原始文件究竟缩小还是变大”的清晰报告。优先补齐这三件事，而不是堆新的专业格式审计小工具。

## v0.56 实际开发任务

1. **macOS HEIC 本机解码（非远程）**：用户手动选择 `.heic` / `.heif`，由 Tauri 命令调用 macOS 系统预装 `/usr/bin/sips` 转为可供现有工作台处理的 PNG。只接受 HEIC 文件签名、≤8 MB 输入、最长边 ≤2048 px、受限像素数，绝不传入由用户控制的 shell 命令。私有临时目录存储解码过程中的文件，操作结束后删除。普通 Chromium 浏览器不伪装具备 HEIC 转换功能。
2. **接入现有图片压缩**：复用 `compressOnePhoto` / `compressPhotoBatch`、现有设置 512/1024/2048 px 和 JPEG/WebP 输出、40–4000 KB 目标；不建立第二套压缩算法和重复目录入口。
3. **保存前真实预览**：“先处理并预览”明确在内存生成实际 ZIP，从 ZIP 中读取转换后的第一张图片做实物预览（不是原始图片截图），可检查模糊、方向、白底、文字。允许“一键压缩并保存 ZIP”的老工作流继续使用；预览后保存直接使用已经处理过的同一批文件，不做内容不一致的第二次编码。
4. **有意义的字节报告**：逐张列出原文件字节、输出字节、分辨率、目标 KB 是否完成、是否更小、实际增加或减少百分比；同时给出整批大小总和、确实变小的文件个数。允许用户保存体积变大的 JPEG 转换文件，但必须说清楚，不把所有格式转换都称作“压缩成功”。
5. **输入/修改隔离**：选择新文件或改变输出格式、分辨率、目标 KB 后，废弃旧结果和旧预览 URL，不覆盖原件，不后台监听文件夹、剪贴板或图库。

## 重要限制

- HEIC/HEIF **只作为输入**，目前输出 JPEG 或 WebP；并非 HEIC 编码器，不支持 Live Photo 视频部分、HDR 全保真、色域/深度/编辑历史的无损保留。源图可能先由系统缩小至 2048 px，再做目标压缩。
- JPEG 无透明通道，白色底层可能改变观感。输出由 Canvas 重新编码，通常不保留原来的 GPS/EXIF 结构，但不能将其宣称为经过认证的隐私匿名化。
- `sips` 依赖安装版 macOS，不支持 Windows/Linux 版或网页预览中的 HEIC 转换；报错应明确、可理解。
- 当前照片单文件上限 8 MB/整批 25 MB/每批 10 张；特别大的原始 iPhone 文件可能被安全限额拒绝，不能偷偷裁掉内容或无声上传转换。
- 转换结果**可能大于原件**；格式兼容性和压缩比是不同目标。每张结果必须在下载前后真实计量和提示。
